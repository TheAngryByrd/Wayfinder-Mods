# Wayfinder Loadouts

> [!WARNING]
> **WIP:** This mod does not currently work. Do not install or use it.
> Saving a loadout can crash Wayfinder. Other loadout operations are incomplete.
> The remaining guide describes intended behavior for development. It does not describe a working release.

The Loadouts design stores named Wayfinder configurations. It is intended to
validate data before it uses inventory, style, Echo, ability, and progression operations.

A profile includes these parts:

- Style items, dyes, weapon styles, and armor styles.
- Armor and accessories.
- Weapons.
- Echoes and their slot positions.
- Item talents and archetype talent nodes.
- Selected abilities.

Loadouts does not grant items or change item ownership.

## Commands

Open the UE console and use these commands:

```text
LoadoutSave <name>
LoadoutApply <name>
LoadoutConfirm
LoadoutCancel
LoadoutDelete <name>
LoadoutRename <old name> <new name>
LoadoutList
LoadoutUI
```

Use quotation marks for a name that contains spaces:

```text
LoadoutSave "Boss Breaker"
LoadoutApply "Boss Breaker"
LoadoutRename "Boss Breaker" "Echo Breaker"
```

`LoadoutSave` overwrites an existing profile with the same name.
Profile names are not case-sensitive.

`LoadoutApply` starts a complete profile without confirmation. Missing parts
and reset notices create a pending confirmation. Use `LoadoutConfirm` or
`LoadoutCancel` when the Loadouts page is not open.

The mod stores profiles in this installed file:

```text
Wayfinder\Atlas\Binaries\Win64\Mods\Loadouts\loadouts.db
```

Do not edit this file while Wayfinder is open.

## In-game UI

Open the Character Loadout screen and select `LOADOUTS`.
You can also enter `LoadoutUI` in the UE console or press `Ctrl+F7`.

The Loadouts page supports these actions:

- Save a new profile.
- Apply or overwrite a profile.
- Rename or delete a profile.
- Refresh the profile list.
- Confirm or cancel a pending application.

Enter a profile name before you select Save New or Rename.
All UI actions use the same service as the console commands.
Profiles are grouped by the equipped Wayfinder, such as Wingrave or Grendel.
Each row shows Armor, Weapon, Style, Echo, Talent, and Ability counts.

A profile without verified equipment slots shows `RECAPTURE REQUIRED`.
Select `Recapture` while the intended Wayfinder is active.
The intended fallback keeps console commands and the quick profile available when the Pak cannot load.

## Quick profile

The default configuration enables these shortcuts:

| Shortcut | Action |
| --- | --- |
| `Ctrl+F5` | Save the `Quick` profile |
| `Ctrl+F6` | Apply the `Quick` profile |
| `Ctrl+F7` | Open the Loadouts page |

Edit this installed file to change the quick profile:

```text
Wayfinder\Atlas\Binaries\Win64\Mods\Loadouts\config.ini
```

Default configuration:

```ini
QuickProfileName=Quick
EnableQuickKeys=1
EnableLoadoutUi=1
```

Set `EnableQuickKeys=0` to disable both profile shortcuts.
Set `EnableLoadoutUi=0` to disable the UMG interface and its shortcut.
Restart Wayfinder after you change this configuration.

## Missing parts and confirmation

Loadouts resolves saved items, Echoes, dyes, styles, talents, and nodes before
it changes the current configuration.

Missing parts or reset notices open an inline confirmation panel.
The panel lists unavailable parts and preserved sections.
Select `Confirm Apply` to continue with verified parts.
Select `Cancel` to keep the current configuration unchanged.

The console uses the same pending confirmation:

```text
LoadoutApply "Boss Breaker"
LoadoutConfirm
```

Loadouts resolves the profile again when you confirm it.
If conditions changed, Loadouts updates the warning and requires another
confirmation. A newer application cannot start while confirmation is pending.

Incomplete Echo data blocks resets for that item only.
Incomplete dye data blocks resets for that item only.
Incomplete talent data blocks the affected item or talent pool.
An incomplete style set or archetype tree remains unchanged.

Talent changes can use Wayfinder reset resources.
The confirmation panel identifies these operations before application.

## Profile database

`loadouts.db` uses schema version 3. The version 3 profile record stores trust
flags for Echoes, talents, archetype nodes, styles, and dyes.

Loadouts reads version 1 and version 2 databases. It converts their Echo and
ability slots to zero-based indices. It marks their reset-sensitive sections
as untrusted because older schemas cannot prove that an empty list was
captured successfully.

Version 1 profiles have no verified equipment-slot names and need recapture.
Other legacy profiles preserve each untrusted section during application.
Overwrite the profile while its intended Wayfinder is active to recapture it.

Database replacement uses these files:

```text
loadouts.db.tmp
loadouts.db.bak
```

Loadouts writes and validates the temporary database first.
It then moves the current database to the backup and installs the validated
file. A failed replacement restores the backup when possible.

If the live database is missing at startup, Loadouts checks the validated
temporary file first and the backup second. It ignores and logs invalid
recovery files.

## Application order

Loadouts applies a profile in this order:

1. Equip the saved character and equipment items.
2. Resolve the profile again after the equipment settles.
3. Apply complete armor styles, weapon styles, dyes, and abilities.
4. Replace Echoes only for holders with complete saved Echo data.
5. Reset and apply only complete changed item talent pools.
6. Reset the archetype tree only after every saved node validates.
7. Ask Wayfinder to save the resulting loadout.

A newer apply request cancels delayed work from an older request.

## Install

This section is only for development tests. Do not install the current version for normal use.

This package does not contain UE4SS. Install the compatible Wayfinder UE4SS
3.0.1 setup first. Enable its `BPModLoaderMod` before you start Wayfinder.

1. Close Wayfinder completely.
2. Extract the Loadouts archive into the Wayfinder installation directory.
3. Permit file replacement when Windows asks for confirmation.
4. Start Wayfinder.

Confirm that these files exist:

```text
Wayfinder\Atlas\Binaries\Win64\Mods\Loadouts\enabled.txt
Wayfinder\Atlas\Binaries\Win64\Mods\Loadouts\config.ini
Wayfinder\Atlas\Binaries\Win64\Mods\Loadouts\dlls\main.dll
Wayfinder\Atlas\Binaries\Win64\Mods\Loadouts\Scripts\main.lua
Wayfinder\Atlas\Binaries\Win64\Mods\Loadouts\Scripts\loadout_ui.lua
Wayfinder\Atlas\Content\Paks\LogicMods\Loadouts.pak
```

The archive includes the required `GUObjectArray.lua` signature.

The native relay remains pinned until Wayfinder exits.
Always restart the game after you replace `dlls\main.dll`.
Do not use a UE4SS mod reload to activate a native Loadouts upgrade.

## Troubleshooting

Use `LoadoutList` to confirm that the profile database loaded.

Run each command after a playable character and inventory are ready.
The mod reports `The loadout data is not ready` before that state.

Wayfinder can reject an equipment, Echo, talent, or ability operation.
The UE4SS log identifies the rejected category or item.

Use `LoadoutCancel` if a console confirmation remains pending.
Do not start another application before you resolve that confirmation.

If dyes remain unchanged, check `LoadoutsNative.log` for `Resolved dye event`.
Loadouts preserves all dyes when the native dye bridge is not ready.

If the database cannot save, preserve `loadouts.db` and `loadouts.db.bak`.
The log reports the failed validation, write, replacement, or restore step.

If the `LOADOUTS` button is absent, enter `LoadoutUI` in the UE console.
The command reports a missing Pak or UMG class. Confirm that `Loadouts.pak`
is in `Atlas\Content\Paks\LogicMods` and that `BPModLoaderMod` is enabled.

If a visible button does not react, confirm that `UE4SS.log` reports the exact
Blueprint button press hook as ready. Also confirm that `dlls\main.dll` exists.
Restart Wayfinder after each native DLL change, then check both logs.
If controller input works but mouse input fails, check for a button input setup
error. Focus artwork must remain hit-test invisible while mouse hover draws it.

## Build

The UMG build requires Unreal Engine 4.27. Run this command from the repository
root and supply its installation directory:

```powershell
.\build.ps1 -Mod Loadouts -UnrealRoot "C:\Program Files\Epic Games\UE_4.27"
```

You can set `WAYFINDER_UE427_ROOT` instead of using `-UnrealRoot`.
Use `-SkipUmgBuild` only when a verified Pak exists under
`build\umg\Loadouts\pak`. The Pak must retain its generated `.sha256` file.
The Loadouts native target rejects `-Configuration Debug` because UE4SS 3.0.1
uses the shipping MSVC standard-library ABI.

The build creates these outputs:

```text
build\native\Loadouts\Release\LoadoutsEventRelay.dll
build\umg\Loadouts\pak\Loadouts.pak
dist\NexusMods\Loadouts
dist\Wayfinder-Loadouts-NexusMods.zip
```

The build cooks the staged `Atlas` project for `WindowsNoEditor`.
It verifies the Pak file list and prints its SHA-256 value.
It does not install files into Wayfinder.

The Source validator parses every Lua file with Lua 5.4.4.
It also checks the UI discovery paths, confirmation API, native dye bridge,
UE4SS virtual table, and native reload-safety contracts.
The Package validator checks required files, Lua hashes, and DLL exports.

## Technical notes

UE4SS 3.0.1 requires a Lua table for each reflected non-const output parameter.
Loadouts supplies output tables to inventory, definition, and loadout calls.
Returned arrays can be Lua tables, while direct object arrays use `ForEach`.
Loadouts handles both forms and converts engine array positions to zero-based
Echo and ability slot indices.

Lua does not call `FindItem`, `FindItemFromId`, or another inventory function
that returns `FInventoryItemEntry`. UE4SS 3.0.1 can corrupt memory while
converting its nested arrays.

The native relay calls the inventory functions with initialized raw parameter
buffers. It copies handles, dyes, abilities, talents, talent pools, Echo IDs,
Echo handles, and Echo-slot counts before it destroys each buffer. It returns
only serialized scalar values to Lua. Lua validates the complete requested
handle before it accepts the snapshot. Any invalid value stops capture without
writing the database.

The Lua service does not scan inventory replicators, call
`GetInitialChangesForAllItems`, or retain an `InventoryItemEntry` wrapper. Item
and style labels use stable data-row names.

Capture reads the component-owned loadout and equipment-slot arrays directly.
It reads archetype nodes from the current character's direct tree data.
It does not call reflected helper functions that return unsafe nested arrays.
It does not retain `InventoryLoadoutItem.AttachedFogSouls`, because that nested
view can expire after its outer loadout callback. The native snapshot reads
`InventoryItemSpec.FogSouls` instead.

Wayfinder exposes live GUID words as signed 32-bit integers.
Loadouts stores canonical unsigned words, accepts legacy signed records, and
converts each word back to signed form when it constructs a reflected handle.

Lua cannot safely convert a dye map table to a reflected `TArray`.
The native scalar bridge builds the array and calls this validated UFunction:

```text
/Script/Wayfinder.PlayerInventoryComponent:ApplyDyeToItem
```

Lua passes the live inventory object's full path. The bridge resolves that
path and verifies the inventory and both data tables before `ProcessEvent`.

The UI loads the exact Character Loadout Blueprint class.
It registers that class's `Construct` hook and performs one startup scan.
It uses only the exact Wayfinder access-button Blueprint class.
It builds the page and configures controller-input ownership before it adds
the page to the Airship stack. A Character player-screen root has no panel
parent, so the UI passes `nil` and uses Airship's player-screen host. The
managed page stays under Airship control until Airship removes it.
It applies the final visibility, enabled state, and pointer methods after the
Blueprint visual setup. The inner Airship button owns the mouse hit test.
The inner button sets separate `DownAndUp` policies for mouse clicks and
controller presses. Airship focus is accepted only when `TakeFocus` returns
true.
Full-button focus artwork uses `HitTestInvisible` while it is visible.
It registers the access button's exact Blueprint press event because this
bytecode-only handler is not guaranteed to enter the native ProcessEvent relay.

The UI does not use `NotifyOnNewObject`, a generic UserWidget Construct hook,
a Wayfinder popup, or a standard UMG button fallback.
Menu stack presence controls page lifetime. The top page controls input.

The native module pins itself before it registers one ProcessEvent callback.
Each queued event has a generation. Dispatch rejects an event from an older
generation after a Loadouts instance stops.
The native bridge does not cache the asset-owned Blueprint press UFunction.
